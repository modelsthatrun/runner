# Contributing

There are two ways to help, and only the second one needs a pull request.

## 1. Measure a model on your GPU

Run `./mtr bench <model>` and `./mtr submit <model>`, as the [README](README.md) shows. Results go through the review inbox, not through git. Nothing else to do.

- **One record per checkpoint is enough.** Measuring again on another day is welcome too. A second contributor with the same GPU turns a result from *unverified* into *reproduced*.
- **Use a clean checkout of a public commit.** If you changed the tool or an adapter, records can't be submitted. Open a pull request with the change instead.
- **If something looks wrong in a result,** open an issue with the `mtr-result` line and `mtr doctor`'s output. That covers wildly different speed, a crash or `OOM` where others fit.

## 2. Add or fix a model adapter

A model is listed on ModelsThatRun only if all of these hold:
- It has **public code** that runs inference.
- It has a **public checkpoint.** Gated downloads are fine. "Weights on request" isn't.
- It **runs on one consumer GPU** at its official default input size: 24 GB at most.

Measuring it, here and on the reference RTX 4090, starts with an adapter.

### Steps

1. **Start the directory.** `./mtr new <id>` for an image model, or `./mtr new <id> --kind llm` for a GGUF language model.
   - The id is the family's slug, such as `rf-detr` or `qwen3`. Sizes are its checkpoints: `nano`, `medium`, or `8b-q4_k_m` for a GGUF.
2. **Write `adapter.py` from the official README**, not from a third-party wrapper. Follow its default input size, its loading code and its inference call. [docs/adapters.md](docs/adapters.md) has the interface, and every directory in `models/` is a working example.
3. **Pin the environment in `pyproject.toml`.** Pin the official package and torch at exact versions.
   - The first `./mtr check` writes `uv.lock`. Commit it.
   - If you change `pyproject.toml` later, run `uv lock --project models/<id>` and commit both files.
4. **Check every size.** Run `./mtr check <id> --size <size>` for each. It must end with `"status": "ok"`.
5. **Score it, optionally.** Run `./mtr eval <id> --size <size> --benchmark <benchmark>`. Compare with the number the paper or README reports for the same benchmark, and mention any gap above about 0.5 AP or 1 point. Don't change anything to close it.
6. **Open a pull request** with `adapter.py`, `pyproject.toml`, `uv.lock`, `.python-version` and any `fixes/`. The template asks for:
   - **the license sources:** the URL of the repository's LICENSE file and of each checkpoint's model card or release notes, with the date you read them. Sizes within one family can carry different licenses.
   - **the `mtr-result` line** of each size's `check`
   - **what the paper reports,** with its exact source ("paper, table 2"), if you compared

### Rules for adapters

- **One call is what a user's code does.** `predict()` covers pre-processing, the forward pass and post-processing, so the output must be usable as it comes back. No caching between calls, and no work hidden in `load()` that a real call would do.
- **The official precision.** List what the official code supports in `PRECISIONS`. The tool picks fp16 if listed, else fp32.
- **Language models.** Prefer the GGUF that the model's own organization publishes. If there is none, a third-party quantization may be used. Say which in the pull request. Pin `revision` to the repository's 40-hex commit.
- **Weights stay out of git.** Torch hub and Hugging Face keep them in their own caches. For packages that download into the working directory, use `mtr_measure.weights_dir("<id>")`.
- **Patches.** If the official code needs a fix to run, put the patch in `models/<id>/fixes/` with a short README saying why. The patch keeps the upstream project's license. The model's page links it as "runs with fixes".

## Changing the tool

Bug fixes and portability fixes are welcome. Changes to the protocol are not taken from pull requests:
- `protocol.py`
- the timing images
- the prompt sets
- the thresholds

Any of them would mean measuring every model again, so open an issue to discuss them first.

- **Tests.** `uv run --frozen --project tools/measure pytest tools/measure/tests -q`. They need no GPU, and CI runs them.
- **Style.** Match the surrounding code and its comments. Messages end in a hint that says what to do next.
- **Record schemas.** The files in `tools/measure/src/mtr_measure/schema/` are generated by the site's schema package. Propose changes in an issue.
